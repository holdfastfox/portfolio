Organizations — the scoping model that runs the platform

Designing the selector and scoping model that decides what every user sees — and making it hold up under deep, messy hierarchies.

Role
Product designer — interaction design, shipped UI
Context
Enterprise developer-tools platform
Focus
Model → resilient states → shipped UI
Collaboration
Engineering, design system

The problem

The organization selector is the lens the entire platform is seen through — it scopes data, permissions, and navigation. It's also tiny and easy to underestimate. As customers grew, their hierarchies got deep and their names got long, and the original selector started to buckle — slow loads, failures, deep nesting, and "wait, which org am I even in?"

Constraints

  • It governs everything. A bug here doesn't break one screen — it scopes the whole product wrong.
  • Hierarchies get deep. The model had to stay legible as organizations nested several levels down.
  • Resilient by default. Loading, error, and empty states couldn't be afterthoughts.
  • Small surface, big stakes. Every pixel of a control this central is load-bearing.

How I worked

01

Map the model

Traced how scoping flows through navigation, data, and permissions so the UI matched the real mental model.

02

Design the edges

Treated loading, error, empty, long-name, and deep-nesting as first-class states, not exceptions.

03

Ship

Delivered the selector plus a dedicated management page, in step with engineering.

Designing the edges, not just the happy path

The interesting design work isn't the default — it's everything else. A shorthand label for the global scope looked like a mis-rendered character to real users, so it got replaced with plain language. Error recovery had a subtle trap: dismiss the error modal, reopen the selector, hit the same error again — with no way back to the picker except a buried "switch organizations" link. That path got fixed. Testing with real enterprise organizations surfaced long names that broke the layout; the selector had also been defaulting to a collapsed first node, making users do extra work before they could select anything. Each failure mode became a deliberate design decision.

Key decisions & tradeoffs

  • States as first-class. Designing loading, error, and empty up front cost time but removed whole classes of confusion later.
  • A dedicated management page. Enterprise admins running org-scoped deployments needed to filter and clean up items — too much to cram into the picker. Splitting it out gave administration its own space and kept the picker fast.
  • Graceful truncation, scoped pragmatically. Long names surfaced from testing with real enterprise organizations. The obvious layout breaks got fixed immediately; longer-term naming convention questions were scoped as a deliberate follow-up, not a blocker.

Outcomes

Edges designed, not deferred

Skeleton loading, error recovery, empty states, long-name truncation, and default behavior — all designed explicitly and tested against real enterprise hierarchies before shipping.

Administration gets its own home

Enterprise admins needed to filter and clean up org-scoped deployments — too much for a picker. A dedicated management page gave them the room to do it.

Less "where am I?"

Modal copy was updated to name the current organization. The default collapsed state — which made users do extra work before selecting — was caught in testing and corrected before launch.

What it taught me

A control this small touches everything — the edge cases are the design.
