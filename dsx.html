Design Language Staging — color at the foundation

Color tokens pinned to brand hex couldn't clear WCAG in light mode. One pull request re-founded the system on ten tonal ramps — and the structure outlasted the project.

Role
Product designer — color systems, documentation
Context
Enterprise SaaS platform design language
Focus
Color architecture → semantic re-aliasing → documentation
Collaboration
With a collaborating designer

The project

The Design System Explorer was a staging ground — a live, themeable gallery for testing a new visual direction before committing engineering time to it. A collaborating designer built the machine: a multi-page component gallery with a top-bar theme builder, shareable URL state, and light and dark mode. Thirty-five pull requests over three weeks.

I came in when light mode landed. The problem was immediate.

The problem

Color tokens were pinned to brand-exact hex values. Brand hex is chosen for aesthetics. It doesn't guarantee legibility. In light mode, the success color couldn't clear WCAG. Info and Active were on the wrong stops. The middle of every ramp was hard to work with. The system needed to be re-founded on ramps.

Constraints

  • Work inside a fast cadence. My collaborator was shipping 35 PRs in three weeks. The work had to land without breaking his flow.
  • Clear WCAG in both modes. Every status semantic — success, info, active, danger — had to pass AA in light and dark.
  • Don't break what's downstream. Tokens feed base styles, which feed components. Wrong tokens break everything they touch.
  • Move fast. This was a staging ground. It needed to work, not be perfect.

At a glance

01

Map the failures

Identified where brand hex was causing accessibility gaps and where semantic tokens were on the wrong stops in light mode.

02

Build the ramps

Ten ramps — neutral, warm-grey, blue, teal, green, lime, violet, magenta, red, gold — each running 50 to 900 in ten stops. Brand hues anchored to specific stops, marked in documentation.

03

Re-alias and document

Semantic tokens re-pointed from raw hex to ramp stops. A standalone color documentation page with contrast badges on every stop, mode-gated status chips, and a proposed-vs-current comparison table.

Ten ramps, re-founded semantics

Brand hues landed on specific stops inside each ramp — marked as anchor points in the documentation. Semantic tokens pointed at those stops, not raw hex. Success shifted two steps darker in light mode to clear AA. Info moved off the brand anchor to a blue ramp stop that passed. Active moved to a violet stop. Danger stayed on a red stop that cleared AA as a white-text fill. The product-surface categorical color set was collapsed into a six-strand system shared across all surfaces.

Illustrative — recreated for portfolio; placeholder hex values, not the production token set

Key decisions & tradeoffs

  • Ramps over brand hex. Brand values are chosen for aesthetics, not legibility. Pinning tokens to brand hex makes every mode decision a one-off fix. Ramps give the system a foundation where accessibility is a property of the stop, not a judgment call each time.
  • Mode-aware semantic layer. Success in dark mode and success in light mode are not the same color. The semantic layer was designed to make that explicit — each status semantic has a ramp stop for each mode, chosen to clear AA.
  • Documentation as part of the work. The color page wasn't an afterthought. Contrast badges on every stop, brand ribbons on anchor stops, mode-gated status chips that show only the current mode's values, a comparison table with mode-tinted cells. The page explains the reasoning, not just the values.
  • One token layer, clear seam. The ramp architecture created a clean boundary: I could rewrite the token layer without touching component CSS. My collaborator could keep shipping components without waiting on the color work.

Outcomes

One PR, merged same day

A large single pull request touching dozens of files. My collaborator built on the new ramps the next day without waiting.

WCAG cleared in both modes

Mode-aware semantic tokens made light-mode accessibility a property of the system — not a manual fix applied stop by stop.

The ramps carried forward

The project was archived a week later when a different visual direction won. The ten-ramp token structure moved into that direction unchanged.

What it taught me

A color system built on brand values is fragile — brand values are chosen for aesthetics, not legibility.

Ramps are the only foundation that holds. The work also confirmed something about collaboration: clean token seams let two designers work in parallel. I rewrote the token layer; my collaborator built on top of it the next day.
